# Tank Royale Rumble bots

> **Public Beta.** This catalog is live and its bots are ranked, but the Rumble is still being finished. Tell us what is confusing or broken in the [issue tracker](https://github.com/robocode-dev/rumble-bots/issues/new).

`rumble-bots` is the reviewable, source-only catalog of bots eligible for ranked Tank Royale Rumble battles. Authors submit bots through pull requests; clients consume the generated `bots/index.json` catalog and run exactly the source tree named by its SHA-256 hash.

See the [bot author guide](https://robocode.dev/rumble/bot-author-guide) for the public submission journey, the [battle contributor guide](https://robocode.dev/rumble/client-guide) to run ranked battles, or the [live rankings](https://robocode-dev.github.io/rumble-data/).

## Submit a bot

1. Choose a [runnable bot template](templates/README.md) and follow its copy-and-rename instructions into `bots/<platform>/<BotName>/`.
2. Include `<BotName>.json`, `<BotName>.sh`, `<BotName>.cmd`, and source code that uses an official Tank Royale Bot API.
3. Declare one permitted SPDX license: [MIT](https://choosealicense.com/licenses/mit/), [Apache-2.0](https://choosealicense.com/licenses/apache-2.0/), [BSD-3-Clause](https://choosealicense.com/licenses/bsd-3-clause/), or [GPL-3.0-or-later](https://spdx.org/licenses/GPL-3.0-or-later.html). The [Choose a License comparison](https://choosealicense.com/licenses/) explains their common permissions and conditions.
4. Run `python scripts/validate_bot.py --root . --owner <your-forge-account> --smoke` before opening a pull request.

Read [CONTRIBUTING.md](CONTRIBUTING.md) for the full submission, ownership, licensing, and moderation rules. The [template guide](templates/README.md#smoke-check-and-executable-scripts) explains smoke markers, runtime prerequisites and executable bits. JSON-only TwinDuel teams use the [team template](templates/README.md#json-only-twinduel-team). Local smoke checks only prove source startup; GitHub moderation runs an isolated, complete one-round battle before a clean bot-only PR can be merged automatically.

## Catalog

`bots/index.json` and `bots/owners.json` are generated by CI. Bot authors must not edit them; only the trusted catalog publisher opens generated-file pull requests, which the moderator App verifies before merge. A catalog entry contains the bot identity, owner, source path, source-tree SHA-256, active lifecycle status, and `teamMembers`. Individual bots publish an empty member list; a TwinDuel team publishes exactly two active `<name> <version>` member identities, so a member release always forces the team entry to be resubmitted. A team directory contains nothing but its own JSON, its members may live under different platform directories, and its published platform is the members' shared platform or `Mixed`. Only `active` entries are eligible for matchmaking.

This repository is designed to be forkable: its validator is standard-library Python. Pull-request assessment runs bot source with read-only permissions inside a restricted container; a separate trusted job makes the exact-commit review and merge decision. After merge, the `main` publisher verifies moderation and regenerates catalog data without launching bot code. See [moderator App setup](GOVERNANCE.md#moderator-app-registration) and [Actions permissions](GOVERNANCE.md#github-actions-permissions) for deployment and recovery.
