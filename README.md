# Tank Royale Rumble bots

`rumble-bots` is the reviewed, source-only catalog for bots and TwinDuel teams that may compete in ranked Tank Royale Rumble battles.

Want to enter the competition? Start with [Submit a bot to the Rumble](https://robocode.dev/rumble/bot-author-guide). It explains the complete journey from local practice to a merged catalog entry. This README is the technical reference for the catalog repository.

## Submission quick reference

1. Fork this repository and create a branch.
2. Add your working bot under `bots/<platform>/<BotName>/`, using `java`, `csharp`, `python`, or `typescript` as the platform directory.
3. Include `<BotName>.json`, `<BotName>.sh`, `<BotName>.cmd`, and source that uses the official Tank Royale Bot API.
4. Declare `MIT`, `Apache-2.0`, `BSD-3-Clause`, or `GPL-3.0-or-later` in the config's `license` field.
5. Run the validator before opening a pull request:

```shell
python scripts/validate_bot.py --root . --owner <your-github-account> --smoke
```

Read [CONTRIBUTING.md](CONTRIBUTING.md) for the complete source, ownership, versioning, licensing, team, and review rules.

## TwinDuel teams

A TwinDuel team is a catalog entry whose `teamMembers` contains exactly two member slots backed by active `<name> <version>` identities. Both slots may name the same bot version. Its directory contains only the team's JSON configuration and has no source or boot scripts of its own.

The members may use different Bot API languages. The generated catalog publishes their common platform when both match and `Mixed` when they do not. A member version change requires a new team version that names the updated member identity.

## Generated catalog

`bots/index.json` and `bots/owners.json` are generated by CI and must not be edited in a pull request. A catalog entry records the bot identity, owner, source path, source-tree SHA-256, lifecycle status, and team membership. Only active entries are eligible for matchmaking.

The catalog is designed to be checked and reproduced. Clients fetch the exact source commit and verify every cached source tree against the published SHA-256 before using it in a ranked battle.
